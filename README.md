# Capacity Connect Portal

Create a complete frontend-only web application named CAPACITY CONNECT, a professional Digital Capacity Building & Learning Management Portal. IMPORTANT: FRONTEND ONLY — do not build Supabase, database, API, real authentication, backend logic, file storage or complex functionality. Use only mock/static data and frontend state. Build the complete UI with React and reusable components, responsive desktop/tablet/mobile design, clean premium government/enterprise styling, white background, navy/blue accents, modern typography, cards, tables, charts, badges, modals, dropdowns, tabs, search, filters, notifications and sidebar navigation. Create three separate role-based dashboard experiences: Trainee, Trainer and Admin, with frontend routing/navigation between all screens. Trainee: Dashboard, Profile, Courses, Course Details, Learning Resources, Progress, MCQ Assessment/Quiz, Results, Certificates, Achievements, Feedback, Notifications and Settings. Trainer: Dashboard, Profile, My Courses, Create/Edit Course UI, Course Details, Resource Library, Upload Resource UI, MCQ/Questionnaire Builder UI, Enrolled Trainees, Performance, Participation, Feedback, Notifications and Settings. Admin: Dashboard, Analytics, User Management, Trainee Management, Trainer Management, Approvals, Role Management, Course Management, Enrollments, Assessments, Certificates, Content Approval, Announcements, Notifications, Achievements, Competency Mapping, Trainer Matching, Reports and Settings. Make every screen visually complete with realistic mock data; no blank placeholder pages. Add working frontend interactions such as navigation, tabs, dropdowns, search/filter, modals, buttons, progress bars, quiz timer UI and chart displays using local mock data. Admin dashboard should show users, trainers, courses, enrollments, assessments, completion rate, certificates, recent activity and pending approvals. Competency Mapping should visually show skills/subjects and suitable trainers with match percentages using mock data. Keep all data in simple local mock files/state so a backend developer can replace them later. Do not regenerate, refactor or add unnecessary features; prioritize completing the frontend UI for all three dashboards and their main pages in the simplest implementation possible.
